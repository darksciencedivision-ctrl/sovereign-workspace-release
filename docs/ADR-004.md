# ADR-004 — SOW readiness mode and absolute executable chain

**Date:** 2026-08-21
**Status:** Accepted
**Reversible:** yes

## Context

SOW is an Electron application. Its readiness cannot be determined by an HTTP health check. The directive offers three options: (i) process + MainWindowTitle probe, (ii) selfcheck receipt file only, (iii) hybrid. The executable chain must be absolute and never touch `npm.cmd`.

## Decision

### Readiness mode: Hybrid (iii)

**Startup test:** Uses the selfcheck receipt file path.

1. Adapter sets `SHELL_SELFCHECK=1` and `SOW_CONDUCTOR_AUTOLAUNCH=0` in the environment
2. Spawns `electron.exe` with `cwd` = `${root}/apps/desktop`
3. The selfcheck (`1` = default 16A pane-I/O check) spawns a supervised pane, asserts the banner renders into the xterm buffer, types a probe, asserts the echo renders, writes `docs/evidence/receipts/PHASE16A_SELFCHECK.json` with `ok: true`, and exits
4. The shell polls for the receipt file up to `timeout_s` (60s recommended)
5. On receipt with `ok: true` → `READY`; the electron process exits naturally
6. On timeout → `FAILED(TIMEOUT)`; the process is terminated

**Normal start:** Process-alive probe.

1. Adapter sets `SOW_CONDUCTOR_AUTOLAUNCH=0` (always)
2. Spawns `electron.exe`
3. The shell polls for process aliveness (process has not exited) up to `timeout_s`
4. Process alive → `READY`. The operator opens the Electron window themselves.

### Selfcheck name and SHELL_SELFCHECK value

- **Name:** `1` — the default 16A pane-I/O selfcheck. This is the fastest and simplest check: no live calls, no model probes, no provider spend. It verifies the real `term.onData → input IPC → PTY → echo → render` wiring.
- **`SHELL_SELFCHECK` value:** `1`

### Absolute executable chain

- **Electron binary:** `${root}/apps/desktop/node_modules/electron/dist/electron.exe`
- **cwd:** `${root}/apps/desktop`
- **argv:** `[${root}/apps/desktop/node_modules/electron/dist/electron.exe, .]`
- This is verified by `selfcheck/run.js:41` — `const electron = require("electron");` which resolves to the electron.exe path string.
- `npm ci` must be run in `modules/sow/apps/desktop/` during Phase 2 to install electron.

### Quota guard

- `SOW_CONDUCTOR_AUTOLAUNCH=0` is ALWAYS set in `env_set`
- Layer 1 (static): adapter schema validation rejects any SOW adapter without `env_set.SOW_CONDUCTOR_AUTOLAUNCH == "0"`
- Layer 2 (spawn): immediately before `CreateProcess`, assert the compiled env contains `SOW_CONDUCTOR_AUTOLAUNCH=0`

## Alternatives considered

1. **Process + MainWindowTitle probe** — rejected: fragile across Electron versions, window manager states, and headless contexts
2. **Selfcheck receipt only** — rejected: only works for startup test; normal operator start needs a different mechanism
3. **`node.exe` from system** — rejected: not workspace-owned. The Electron binary is the workspace-owned runtime.
4. **`npm.cmd` / `npm start`** — rejected: §1.1, A-14 forbid shell wrappers

## Consequences

- The startup test takes ~15-30s (selfcheck boot + pane I/O exercise)
- The selfcheck receipt is a machine-readable JSON file
- The normal start is a simple process-alive check (fast)
- `npm ci` must succeed during Phase 2 install for the electron binary to exist
- The `SOW_CONDUCTOR_AUTOLAUNCH=0` guard is enforced at two layers, preventing any provider spend

## Encoded (appended by REM-01 R3-11, 2026-08-21)

This section records how decision (iii) was encoded in the adapter, and one correction to the
path the REM-01 directive stated. Nothing above this line was altered.

### What `SHELL_SELFCHECK=1` actually does

FACT[modules/sow/apps/desktop/main.js:2760] `if (process.env.SHELL_SELFCHECK) {` gates the whole
in-Electron self-check block.

FACT[modules/sow/apps/desktop/main.js:2764-2793] The value selects which self-check runs. The
chain tests for named values (`picker`, `conductor`, `fully-live`, and about twenty others) and
line 2793 ends it with `: "pane-io"`. `SHELL_SELFCHECK=1` matches none of the named values, so it
falls through to **`pane-io`**. The comment at main.js:2761-2763 states this as the intended
back-compat behaviour.

FACT[modules/sow/apps/desktop/selfcheck/pane-io-selfcheck.js:26-28] The pane-io check writes to

```js
const RECEIPT_PATH = path.resolve(
  __dirname, "..", "..", "..", "docs", "evidence", "receipts", "PHASE16A_SELFCHECK.json"
);
```

`__dirname` is `<root>/apps/desktop/selfcheck`, so three `..` levels resolve to `<root>`. The
receipt path is therefore:

    ${root}/docs/evidence/receipts/PHASE16A_SELFCHECK.json

**Correction.** REM-01 R3-11 specifies
`${root}/apps/desktop/docs/evidence/receipts/<CONFIRMED-NAME>.json`. That is one directory level
too deep — it would resolve to `<root>/apps/desktop/docs/...`, which does not exist. The confirmed
path above is what the code writes and is what `shell/modules/sow.json` now encodes. Verified on
disk: `<root>/docs/evidence/receipts/PHASE16A_SELFCHECK.json` exists and contains
`"check": "phase-16a.pane-io"` with `"ok": true`.

FACT[modules/sow/apps/desktop/selfcheck/receipt-path.js:19] Note that the shared `receiptPath()`
helper resolves the same directory and honours a `SHELL_SELFCHECK_RECEIPT_DIR` override — but
`pane-io-selfcheck.js` does **not** use that helper; it hardcodes the path shown above. The
override therefore does not apply to the pane-io receipt, and `runtime_writes` must declare the
default directory.

FACT[modules/sow/apps/desktop/main.js:2750]
`if (!process.env.SHELL_SELFCHECK && process.env.SOW_CONDUCTOR_AUTOLAUNCH !== "0") {` — conductor
autolaunch is skipped when *either* condition holds. Under the startup test both hold, so the
provider-spending path is doubly excluded. This is HC-7 / H-10 confirmed in the module's own
source, not merely in our adapter.

### What was encoded

`shell/modules/sow.json`:

```json
"startup_test": {
  "env_set": { "SHELL_SELFCHECK": "1" },
  "readiness": { "kind": "receipt_file",
                 "path": "${root}/docs/evidence/receipts/PHASE16A_SELFCHECK.json",
                 "require": { "ok": true }, "timeout_s": 90, "poll_ms": 1000 } }
```

`shell/modules/schema.json` gained an optional `startup_test` object with
`additionalProperties: false` at both levels, containing only `env_set` and `readiness`;
`readiness.kind` is an enum of exactly `["receipt_file"]`.

`identity` changed from `{"kind": "process_path", "path_prefix": …}` to `{"kind":
"process_image"}`. The compiler sets `identity.expected_image` to the compiled `argv[0]`, and
`ModuleRunner._identity` compares `_canonical(QueryFullProcessImageNameW(pid))` to
`_canonical(expected_image)` for **equality**. `path_prefix` is now rejected by the validator:
prefix comparison on a path is the class of check H-5 forbids.

`runtime_writes` was corrected from `${root}/apps/desktop/docs/evidence/receipts` to
`${root}/docs/evidence/receipts` for the same reason as the readiness path.

### Receipt staleness

INTERPRETATION: `PHASE16A_SELFCHECK.json` is a committed gate artifact that already exists on
disk with `"ok": true` before any startup test runs. A readiness probe that only checks existence
and `ok` would pass instantly against the stale file and prove nothing. `receipt_file_probe` now
takes `newer_than` (the launch timestamp) and ignores any receipt whose mtime predates it. This
is a correctness fix to an existing readiness kind, not a new feature.

Reversible: yes — reverting `sow.json`, the two schema additions and the `newer_than` argument
restores the prior behaviour.
