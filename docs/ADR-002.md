# ADR-002 — SOVEREIGN launch vector and identity fingerprint

**Date:** 2026-08-21
**Status:** Accepted
**Reversible:** yes

## Context

SOVEREIGN 3.1.2 is distributed as a zip with a `Start-Sovereign.ps1` launcher. The directive forbids launching through PowerShell (§1.1). The adapter must replicate the launcher's pre-checks in Python and spawn the server directly.

The pre-checks are load-bearing: the launcher validates the root marker, required files, Python environment, imports, SYSTEM_MANIFEST, Ollama model availability, and port availability — and throws before spawning if any check fails. Missing Ollama models → `FAILED(PRECHECK:...)`.

## Decision

**Launch vector:** The adapter replicates `Start-Sovereign.ps1`'s pre-checks in Python:

1. Validate `.sovereign-root` marker file contains `SOVEREIGN_ROOT_MARKER=1`
2. Verify `SYSTEM_MANIFEST.json` and `ui/ui_shell/dist/index.html` exist
3. Verify `.venv/Scripts/python.exe` exists
4. Verify `import flask, requests, sovereign_product, sovereign_product.server` succeeds
5. Parse `SYSTEM_MANIFEST.json` → extract Ollama base URL and 5 required model assignments
6. Query Ollama `GET /api/tags` and verify all 5 required models are present
7. Check port 5175 is free
8. Spawn: `[.venv/Scripts/python.exe, -m, sovereign_product.server, --root, <root>, --host, 127.0.0.1, --port, 5175, --workers, 1]`
9. Poll `GET /v1/health` for `{"status": "ok"}` up to 45s
10. After readiness, verify the listener is loopback-bound

**Identity fingerprint:** `GET /v1/health` → must return JSON with `status: "ok"` and `product_version` present.

**Pre-check failure behavior:** Any pre-check failure → `FAILED(PRECHECK:<message>)`. The module never spawns.

## Alternatives considered

1. **Subprocess the PowerShell script** — rejected: §1.1 forbids PowerShell wrappers
2. **Skip pre-checks, just spawn** — rejected: the pre-checks are a safety feature. Missing models = the server would start but be non-functional. The directive requires honest states.
3. **Delegate pre-checks to the adapter's launch phase only** — accepted: the adapter is the single authority for pre-checks

## Consequences

- The adapter is ~150 lines of Python for pre-checks
- `SYSTEM_MANIFEST.json` parsing is required (the file is JSON, straightforward)
- If Ollama models change, the adapter must be updated (but the manifest is the source of truth)
- The `--workers 1` flag keeps the process count minimal for the shell's Job Object
