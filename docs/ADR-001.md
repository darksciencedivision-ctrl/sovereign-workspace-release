# ADR-001 — Architecture: Local web shell with ThreadingHTTPServer

**Date:** 2026-08-21
**Status:** Accepted (by directive §7.1)
**Reversible:** no

## Context

The Sovereign Workspace Shell must give the operator one front door to four systems without modifying any of them. Each module has its own runtime, UI, and lifecycle. The shell must be local-only, dependency-free at runtime, and reproducible.

## Decision

Local web shell architecture:
- **Backend:** Python 3.12 stdlib `ThreadingHTTPServer` on `127.0.0.1:5180`
- **Frontend:** Single `index.html` + `app.css` + `app.js`, < 300 KB, no framework, no bundler, no CDN
- **Backend responsibilities:** adapter compile/validate, Job-Object supervision, readiness + fingerprint probing, startup-test records, log ring buffers, pre-flight probes, Distillery parsing
- **Explicitly rejected:** proxies, in-process modules, Electron wrapper, admin rights, restyling/injecting/proxying/iframing module UIs

## Alternatives considered

1. **Electron shell** — rejected: adds ~200 MB of runtime dependencies, violates HC-8
2. **Proxy all modules through the shell** — rejected: violates HC-3 (no proxying)
3. **CLI-only tool** — rejected: operator requested a web GUI

## Consequences

- The shell is a web server that the operator opens in a browser
- Module UIs open in their own browser tabs (web) or windows (Electron)
- No framework dependency means more boilerplate code but zero runtime deps
- ThreadingHTTPServer is sufficient for single-operator local use

## Evidence

Directive §7.1, HC-5, HC-8
