# ADR-003 — Debate Table identity fingerprint

**Date:** 2026-08-21
**Status:** Accepted
**Reversible:** yes

## Context

Debate Table v1.2 P1 has no `/health` endpoint. The directive requires an identity fingerprint that goes beyond `/ → 200`. The module starts without Ollama by design (controls disable, turns fail safely), so the fingerprint must not depend on Ollama reachability.

## Decision

**Two-part identity probe:**

1. `GET /api/models` → must return JSON. The response shape is validated:
   - If `"ollama_reachable"` key exists and is `false`, that is a valid identity response (Ollama unreachable is a normal state for Debate Table)
   - If `"models"` key exists (array), that is also valid
   - Either path confirms the Debate Table API is responding

2. `GET /` → response body must contain the string `"Debate Table"` (the page title / H1 text)

Both must pass for identity to be confirmed.

## Alternatives considered

1. **`/ → 200` only** — rejected: directive explicitly says this is not sufficient
2. **`/api/models` only** — rejected: the route could change; the HTML marker is more stable
3. **`/api/topic` response shape** — considered but rejected: the topic endpoint may return different shapes depending on state

## Consequences

- Two HTTP requests per identity probe (both cheap, localhost)
- The HTML substring match is simple but effective
- If the Debate Table frontend is redesigned, the marker string may need updating (but the shell is versioned alongside the modules)
