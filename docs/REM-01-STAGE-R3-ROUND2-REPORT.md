## G4-3 — H-4 had no test and no artifact

FACT[shell/tests/test_frontend.py] Five tests:

- `test_no_dangerous_dom_sinks` — scans every `shell/static/*.js` line for `innerHTML`,
  `outerHTML`, `insertAdjacentHTML`, `eval(`, `new Function`, `document.write`. Zero hits across
  901 lines of `app.js`. The allowlist is a module-level dict and is **empty**; the artifact
  prints it so a reviewer can see whether it ever grows.
- `test_no_inline_script_or_handlers` — `index.html` has no inline `<script>` block (only
  `<script src="app.js" defer>`), no `on*` attribute, no inline `<style>`. This is what makes the
  `script-src 'self'` CSP satisfiable rather than merely declared.
- `test_dynamic_text_uses_textcontent` — asserts the rendering path uses `textContent`.
- `test_script_tag_returned_as_json_string` — writes
  `<script>alert("xss")</script> & <img src=x onerror=alert(1)> </script>` into a ring buffer,
  fetches `/api/logs/frontend` from the real handler, and asserts: `Content-Type:
  application/json`, `X-Content-Type-Options: nosniff`, `frame-ancestors 'none'`, the body parses
  as JSON, the payload round-trips intact inside the `logs` string, and the embedded double
  quotes are escaped on the wire as `alert(\"xss\")`.
- `test_payload_is_not_altered_by_redaction` — control, so the round trip proves escaping rather
  than accidental deletion of the payload.

INTERPRETATION, stated precisely so the artifact is not over-read: `json.dumps` escapes quotes
and backslashes, not `<` or `>`. What makes the payload inert is the combination of (a) it is
data inside a JSON string, (b) the response is served as `application/json` with `nosniff` so no
browser will parse it as a document, and (c) the frontend assigns it via `textContent`. The test
asserts all three. It does not claim `<` is HTML-entity-encoded, because it is not.
